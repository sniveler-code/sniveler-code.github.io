# 💻 Custom Nodes

While AI Behavior Architect ships powerful built-in nodes, its real strength is how little code you write to add your own DOTS logic. You write a **plain `partial struct`** with one method; the framework's generator writes the entire ECS boilerplate around it — the `ISystem`, the entity query, the `IJobChunk`, the blackboard plumbing, the delta-time injection, the command-buffer wiring — and Burst-compiles it.

## Step 1 — Write the Struct

Create a C# script anywhere in your project (any assembly that the generated assembly can reference — see [Project Setup](#project-setup)):

```csharp
using SnivelerCode.AiBehavior.Runtime.Attributes;
using SnivelerCode.AiBehavior.Runtime.Components;

namespace MyGame.AI
{
    // The string is cosmetic — it shows up as the node's subtitle in the canvas.
    // The node's *identity* is the fully-qualified struct type name, hashed (FNV-1a).
    [BtCustom("Debug/Log Action")]
    public partial struct LogAction
    {
        // The generator will call this private method inside the generated Burst job.
        // It MUST be named "Process" and MUST return NodeStatus.
        private NodeStatus Process()
        {
            // This runs inside a Burst job — use the Burst-safe logger,
            // not UnityEngine.Debug.Log (which is stripped/unsafe under Burst).
            BtLogger.BurstLog()
                .Append("Hello from Burst! ")
                .Append(42)
                .Log();

            return NodeStatus.Success;
        }
    }
}
```

### The three rules

1. **`partial struct`** — the generator declares the *other half* of the struct (as an `IJobChunk`) in your namespace. Forgetting `partial` is the #1 cause of confusion.
2. **`[BtCustom("…")]` on the struct** — registers the type with the editor's search window *and* with the Roslyn generator.
3. **A `private NodeStatus Process(...)` method** — any access level works as long as it's named `Process`; it must return `NodeStatus`. Any other return type produces compiler error **BA0001** (*"The Process method must return NodeStatus"*).

## Step 2 — Find It in the Editor

Save the script, wait for Unity to compile, then:

1. Open the Behavior Editor → right-click / `Spacebar` → search window.
2. Pick **Actions → Action Custom** — the node's inspector shows a **dropdown of every `[BtCustom]` type** in the project (displayed as `Namespace/StructName`), plus one field per `[BtParam]` parameter.
3. Pick your type from the dropdown. The node is now a fully functional DOTS action.

If the dropdown says **"No actions found"**, your assembly isn't compiled yet, or the type lacks `[BtCustom]`. If a previously-used type disappears from your graph, the node renders **broken** (red border, "Component mismatch" in the inspector) — re-selecting another action fixes it.

## Step 3 — What the Generator Produces

For `MyGame.AI.LogAction` (hash `H` = FNV-1a of `"MyGame.AI.LogAction"`) the Roslyn generator emits, **in your namespace**:

```csharp
// <auto-generated>
namespace MyGame.AI
{
    // The ISystem: builds the query, updates handles, schedules the job
    public partial struct Bt{H:X}System : ISystem
    {
        public struct Tag : IComponentData, IEnableableComponent { }
        // … queries, type handles, OnCreate / OnUpdate …
    }

    // The other half of YOUR struct: a Burst-compiled IJobChunk
    [BurstCompile]
    public partial struct LogAction : IJobChunk
    {
        private const ulong ACTION_HASH = H;
        public ComponentTypeHandle<Bt{H:X}System.Tag> TagHandle;
        [ReadOnly] public ComponentTypeHandle<BtAgent> AgentHandle;
        public BufferTypeHandle<BtActionState> ActionStates;
        // … one handle per Process() parameter that maps to a query component …

        public void Execute(in ArchetypeChunk chunk, int chunkIndex,
                            bool useEnabledMask, in v128 chunkEnabledMask)
        {
            // for each entity whose Tag is ENABLED:
            //   for each BtActionState entry with ActionHash == H and Status == Running:
            //       var status = Process( /* parameters resolved below */ );
            //       state.Status = status;
            // disable the Tag on entities left with no running H-action
        }
    }
}
```

and the **`SystemNodes` registry** (written by the editor) adds `new BaCustom { Index = H, Components = new[] { "MyGame.AI.LogAction" } }` so that:

* **`BtBakingSystem`** (bake time) adds a **disabled** `Bt{H:X}System.Tag` to every agent entity whose tree contains this action — the Tag is the per-agent "I have (or will have) this action" marker,
* **`BtDispatcherSystem`** (runtime) enables/disables that Tag on the agent when a node instance activates/deactivates,
* the action system's job iterates only agents **with the Tag** — and only entities whose *entire query* matches (see the execution model below).

> 💡 **Two generated systems per hash — never per node instance.** Ten agents using the same action share one system; a node's *instance* is identified at runtime by `(ActionHash, NodeIndex)` inside the agent's `BtActionState` buffer, so the same action type can run concurrently at different tree positions on the same agent.

## Step 4 — Reading the Result Back

Return values have fixed meanings (they become the node's `NodeStatus`):

| Return | Meaning |
|---|---|
| `NodeStatus.Running` | keep ticking — `Process` is called again next frame (this is how you build stateful actions: timers, movement, waiting) |
| `NodeStatus.Success` | completed successfully — the node reports Success to its parent |
| `NodeStatus.Failure` | failed — the node reports Failure to its parent |
