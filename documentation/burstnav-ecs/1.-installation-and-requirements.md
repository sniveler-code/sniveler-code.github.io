# ⚙️ Installation & Requirements

## Requirements

BurstNav Free targets the Entities **1.x** line. The package declares its DOTS dependencies in `package.json`, so Unity resolves them for you — but they must be pinnable in your project.

| Requirement | Version | Notes |
|---|---|---|
| **Unity Engine** | **2022.3** or newer | Declared as `"unity": "2022.3"` in `package.json`. |
| **Unity Entities** | `1.2.4` | Pulled in automatically. Verified host: Unity 6000.5.2f1 with `com.unity.entities` 6.5.0. |
| **Burst Compiler** | `1.8.12` | Pulled in automatically. |
| **Unity Collections** | `2.4.0` | Pulled in automatically. |
| **Unity Mathematics** | `1.3.1` | Pulled in automatically. |
| **AI Module** | built-in | Not used at runtime; only a host project's own `NavMesh` code would need it. |

There is no scripting define, no editor setting and no project configuration step. If the DOTS packages compile, BurstNav compiles.

## Install the package

1. Open **Window → Package Manager**.
2. Click **+ → Add package from disk…**
3. Select the `package.json` inside `sniveler-code.dev.burstnav-ecs`.
4. Wait for compilation and confirm the Console has no errors.

The equivalent `Packages/manifest.json` entry for an embedded or local copy looks like this:

```json
{
  "dependencies": {
    "com.unity.burst": "1.8.12",
    "com.unity.collections": "2.4.0",
    "com.unity.entities": "1.2.4",
    "com.unity.mathematics": "1.3.1",
    "sniveler-code.dev.burstnav-ecs": "file:../sniveler-code.dev.burstnav-ecs"
  }
}
```

> 💡 **Keep every `.meta` file.** The GUIDs inside them keep serialized references — authoring components in scenes, subscene references and sample assets — stable across package updates. Deleting `.meta` files makes Unity re-create them with new GUIDs and every baked reference breaks.

## Runtime assembly

| Property | Value |
|---|---|
| Assembly name | `SnivelerCode.BurstNav.Runtime` |
| Root namespace | `BurstNav` |
| `allowUnsafeCode` | `true` |
| `autoReferenced` | `true` |
| References | Unity DOTS assemblies only (`Unity.Entities`, `Unity.Entities.Hybrid`, `Unity.Transforms`, `Unity.Burst`, `Unity.Collections`, `Unity.Mathematics`, `Unity.Jobs`) |

Because the assembly is auto-referenced, a project with **no** assembly definitions can use the package immediately. As soon as your gameplay code lives in its own `.asmdef`, add `SnivelerCode.BurstNav.Runtime` to that file:

```json
{
  "name": "Game.Navigation",
  "rootNamespace": "Game.Navigation",
  "references": [
    "SnivelerCode.BurstNav.Runtime",
    "Unity.Entities",
    "Unity.Burst",
    "Unity.Collections",
    "Unity.Jobs",
    "Unity.Mathematics"
  ],
  "allowUnsafeCode": false,
  "autoReferenced": true
}
```

Add `Unity.Entities.Hybrid` and `Unity.Transforms` when the same assembly also contains authoring components and bakers — assembly references are not transitive.

> ⚠️ **Do not rename the runtime assembly.** Unity resolves assembly references by name; a renamed `SnivelerCode.BurstNav.Runtime.asmdef` breaks every snippet in this documentation.

## Import the samples

1. **Window → Package Manager**.
2. Select **BurstNav Free**.
3. Open the **Samples** tab.
4. Import **Hello Navmesh** or **Funnel Steering**.

Unity copies the sample into `Assets/Samples/BurstNav Free/1.1.0/`, leaving the package copy under `Samples~` untouched. Each sample folder contains one scene, a `Scripts` folder with its own assembly definition, and a README.

If you previously imported samples from an older package version, delete `Assets/Samples/BurstNav Free` before importing again: Unity matches copied assets by path and GUID, so a stale copy silently shadows the new one.

Neither sample needs a SubScene bake — a bootstrap MonoBehaviour builds the graph blob from the Free data types and spawns the agents when Play starts.

## Verify the installation

| Check | Expected |
|---|---|
| Console | No compile errors, no Burst warnings about `SnivelerCode.BurstNav.Runtime`. |
| **Jobs → Burst → Enable Compilation** | On (default). |
| Systems | After a scene with a `BnBlobMeshGraph` runs, `BnPathfindingSystem` and `BnSteeringSystem` appear in **Window → Entities → Systems**. |
| Menu bar | There is no `BurstNav/…` menu — the package ships no editor tooling. |

## Running the tests

The package contains `SnivelerCode.BurstNav.Tests.EditMode` and `SnivelerCode.BurstNav.Tests.PlayMode`. Like any package test set, they compile only when the package is listed under `testables` in `Packages/manifest.json`:

```json
{
  "testables": ["sniveler-code.dev.burstnav-ecs"]
}
```

Then open **Window → General → Test Runner** and run either assembly.
