# 🚀 Quick Start

This page takes an empty project to one agent that follows a path across a baked 4 × 4 navigation grid. Every type and call below is part of the public API.

## 1. Bake a static navigation graph

The navigation graph is immutable at runtime, so it is baked once from a static description:

1. Create a **SubScene** and open it.
2. Add an empty GameObject named `Navmesh`.
3. Add the **BnMeshAuthoring** component.

`BnMeshAuthoring` builds a flat grid of square polygons with directed portals between axis neighbours, and its baker writes exactly one `BnBlobMeshGraph` component whose `Value` points at a `BlobAssetReference<BnMeshGraphBlob>`.

| Field | Meaning |
|---|---|
| `CellsX` | Polygon count along X. |
| `CellsY` | Polygon count along Y. |
| `CellSize` | World-space edge length of one square polygon. |
| `Origin` | Lower-left corner of the grid on the XY navigation plane. |

Polygon ids are row-major — `id = y * CellsX + x` — and never change. A 4 × 4 grid with `CellSize` 1 at `Origin` (0, 0) covers (0, 0) to (4, 4) and contains 16 polygons.

> ⚠️ **Exactly one graph per world.** Both systems skip their work when there is no `BnBlobMeshGraph` singleton or when more than one exists.

## 2. Spawn an agent

1. In the same SubScene, add a GameObject named `Agent` at (0.5, 0.5, 0).
2. Add the **BnAgentAuthoring** component.
3. Set `MaxSpeed` to 5, `Radius` to 0.5 and `StartActive` to true.

The baker creates the dominant agent archetype in one step:

| Component | Purpose |
|---|---|
| `BnAgentSteering` | Position, velocity, desired velocity, speed, radius and path progress. |
| `BnAgentPath` | Path slot state and waypoint count. |
| `BnPathWaypoint` | The path buffer: one element per polygon in the corridor. |
| `BnAgentPathRequest` | The pending search request slot. |
| `BnAgentSteeringActive` | Enableable toggle for the steering chain. |
| `BnAgentPathRequestPending` | Enableable toggle that arms a search request. |

The baker sets `Start` and `Target` to the spawn position and leaves the request toggle disabled, so the agent stays still until you write a target and arm the request.

## 3. Systems are discovered automatically

The default world adds both systems to `SimulationSystemGroup` — nothing to register:

| System | Job | Ordering |
|---|---|---|
| `BnPathfindingSystem` | `BnPathfindJob` | `[UpdateInGroup(SimulationSystemGroup)]` |
| `BnSteeringSystem` | `BnFunnelJob`, `BnSteeringStateJob`, `KinematicBypassJob`, `IntegrateJob` | `[UpdateAfter(BnPathfindingSystem)]`, `[UpdateBefore(EndSimulationEntityCommandBufferSystem)]` |

In a custom `World`, create both inside its `SimulationSystemGroup`. Never call `OnUpdate` manually and never complete their job handles from gameplay code.

## 4. Request the first path

Add this system to your gameplay assembly. It runs once, writes a target into every baked agent request, and arms the request toggle through the end-of-frame command buffer.

```csharp
using Unity.Collections;
using Unity.Entities;
using Unity.Mathematics;

namespace BurstNav.Guide
{
    [UpdateInGroup(typeof(SimulationSystemGroup))]
    [UpdateBefore(typeof(BnPathfindingSystem))]
    public partial class BnFirstTargetSystem : SystemBase
    {
        private EndSimulationEntityCommandBufferSystem _commandBufferSystem;
        private EntityQuery _agents;
        private bool _issued;

        protected override void OnCreate()
        {
            _commandBufferSystem = World.GetOrCreateSystemManaged<EndSimulationEntityCommandBufferSystem>();
            _agents = GetEntityQuery(ComponentType.ReadWrite<BnAgentPathRequest>());
        }

        protected override void OnUpdate()
        {
            if (_issued || _agents.IsEmptyIgnoreFilter)
            {
                return;
            }

            _issued = true;

            using var entities = _agents.ToEntityArray(Allocator.Temp);
            using var requests = _agents.ToComponentDataArray<BnAgentPathRequest>(Allocator.Temp);
            var commands = _commandBufferSystem.CreateCommandBuffer();

            for (var index = 0; index < entities.Length; index++)
            {
                var request = requests[index];
                if (request.Status == BnPathStatus.Ready)
                {
                    continue;
                }

                request.Target = new float3(3.5f, 3.5f, 0f);
                request.TargetPoly = -1;
                request.Status = BnPathStatus.Pending;
                request.RequestId++;
                commands.SetComponent(entities[index], request);
                commands.SetComponentEnabled<BnAgentPathRequestPending>(entities[index], true);
            }
        }
    }
}
```

The command buffer plays back at the end of frame 0. On frame 1 `BnPathfindingSystem` sees the enabled request, runs flat A* to the nearest polygon of the target, and writes the corridor into the waypoint buffer. The steering system then re-enables `BnAgentSteeringActive` and the agent starts moving.

Use a payload that matches the baked agent:

| Field | Value for the first request |
|---|---|
| `Start` | Keep the spawn position. |
| `Target` | World space on the XY plane; **Z is height**. |
| `TargetPoly` | `-1` asks the pathfinder to snap the target to the nearest polygon. |
| `RequestId` | Your own monotonic counter — the pipeline copies it through and never compares it. |

## 5. Verify the first moving agent

Enter Play mode and inspect the `Agent` entity in the Entities Hierarchy.

| Frame | What you should see |
|---|---|
| 0 | `BnAgentPathRequestPending` turns on at the end of the frame. |
| 1 | `BnAgentPath.Status` becomes `Ready` and `WaypointCount` is greater than zero. |
| 2 and later | `BnAgentSteering.Position` moves toward (3.5, 3.5, 0); `WaypointIndex` and `PathProgress` grow. |
| Arrival | `BnAgentSteering.Flags` contains `Arrived` and `DesiredVelocity` returns to zero. |

If the agent stays still, work through this list in order:

1. The world has exactly one `BnBlobMeshGraph` whose `Value.IsCreated` is true.
2. The agent carries all six components and its request toggle is enabled.
3. `BnPathfindingSystem` and `BnSteeringSystem` exist and are enabled.
4. Burst is enabled and the Console shows no job safety errors.
5. The graph is not empty and a route exists between the resolved polygons.

An off-graph start behaves like an off-graph target: both polygons are snapped to the nearest one. A failure therefore means an empty graph (the snap yields `-1`), no route, or an exhausted `MaxIterations` budget — in all three cases `BnAgentPath.Status` becomes `Failed` and the corridor is cleared.

## 6. Build the blob without a SubScene

The same graph can be created from code. Call this one-shot setup before agents run, and dispose the blob when the graph entity is destroyed:

```csharp
using Unity.Entities;
using Unity.Mathematics;

namespace BurstNav.Guide
{
    public static class BnRuntimeGraph
    {
        public static Entity Create(EntityManager entityManager, int cellsX, int cellsY, float cellSize, float2 origin)
        {
            var blob = BnMeshAuthoringBaker.BuildGraph(cellsX, cellsY, cellSize, origin);
            var entity = entityManager.CreateEntity(typeof(BnBlobMeshGraph));
            entityManager.SetComponentData(entity, new BnBlobMeshGraph { Value = blob });
            return entity;
        }

        public static void Destroy(EntityManager entityManager, Entity entity)
        {
            var blob = entityManager.GetComponentData<BnBlobMeshGraph>(entity).Value;
            if (blob.IsCreated)
            {
                blob.Dispose();
            }

            entityManager.DestroyEntity(entity);
        }
    }
}
```

`BuildGraph` returns a **persistent** blob owned by the caller, unlike the authoring baker whose blob is owned by the baking system. Both Free samples use this path: they build the graph at Play start, so their scenes need no bake step at all.
