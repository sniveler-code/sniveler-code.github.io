👋 BurstNav Free — ECS Pathfinding for Unity DOTS

BurstNav Free is a zero-allocation navigation package for Unity DOTS: a baked polygon graph feeds a flat A* search, the search fills a per-agent waypoint buffer, and a kinematic funnel turns that corridor into a smooth desired velocity. Every stage is a Burst-compiled job reading chunk arrays — no NavMeshAgent, no MonoBehaviours, no per-frame allocations.

💡 Why not NavMeshAgent?
NavMeshAgent is an object-oriented wrapper around a managed navigation world. One agent per MonoBehaviour means one transform sync, one callback and one managed object per unit. BurstNav keeps the whole agent state in six ECS components and resolves paths and velocity inside Burst jobs, so hundreds of agents cost chunk iteration instead of main-thread calls.

✨ Core Features

  • 🧊 Static polygon graph in a blob asset — one immutable BlobAssetReference<BnMeshGraphBlob> shared by every job. No graph copies, no per-agent topology.
  • 🧠 Branch-free flat A* — BnAStar.FindPath expands polygons from a single reusable BnPathScratchpad. Steady-state allocation is exactly zero.
  • 🎯 Kinematic funnel steering — portal-based string pulling (BnFunnel) removes the stair-step corridor and returns corner-cutting velocity in one pass.
  • 🧩 Six-component agent archetype — BnAgentSteering, BnAgentPath, BnPathWaypoint, BnAgentPathRequest plus two enableable toggles. One dominant archetype means dense chunks.
  • ⚡ Deferred, allocation-free command buffers — request and steering toggles flip enable bits through EndSimulationEntityCommandBufferSystem; nothing completes a job on the main thread.
  • 🧪 EditMode and PlayMode tests — the package ships a NUnit suite under Tests plus two runnable samples.

🧭 How the pipeline fits together

BnBlobMeshGraph (singleton)
  -> BnMeshGraphBlob (blob asset)
  -> BnAStar.FindPath + BnPathScratchpad
  -> BnAgentPath + BnPathWaypoint buffer
  -> BnFunnel.Solve
  -> BnAgentSteering.DesiredVelocity
  -> KinematicBypassJob
  -> BnAgentSteering.Velocity
  -> IntegrateJob
  -> BnAgentSteering.Position

⚠️ What Free deliberately does not do

Free is a single-agent-quality steering pipeline. It has no local avoidance, no dynamic obstacles and no door/area tags — those stages do not exist in the runtime, so there is nothing to tune or toggle. If a level needs crowds that separate, obstacles that move, or doors that close, read Limitations & Scope before you commit to the package.

🚀 Quick Start

This page takes an empty project to one agent that follows a path across a baked 4 × 4 navigation grid. Every type and call below is part of the public API.

1. Bake a static navigation graph

The navigation graph is immutable at runtime, so it is baked once from a static description:

  1. Create a SubScene and open it.
  2. Add an empty GameObject named Navmesh.
  3. Add the BnMeshAuthoring component.

BnMeshAuthoring builds a flat grid of square polygons with directed portals between axis neighbours, and its baker writes exactly one BnBlobMeshGraph component whose Value points at a BlobAssetReference<BnMeshGraphBlob>.

FieldMeaning
CellsXPolygon count along X.
CellsYPolygon count along Y.
CellSizeWorld-space edge length of one square polygon.
OriginLower-left corner of the grid on the XY navigation plane.

Polygon ids are row-major — id = y * CellsX + x — and never change. A 4 × 4 grid with CellSize 1 at Origin (0, 0) covers (0, 0) to (4, 4) and contains 16 polygons.

⚠️ Exactly one graph per world. Both systems skip their work when there is no BnBlobMeshGraph singleton or when more than one exists.

2. Spawn an agent

  1. In the same SubScene, add a GameObject named Agent at (0.5, 0.5, 0).
  2. Add the BnAgentAuthoring component.
  3. Set MaxSpeed to 5, Radius to 0.5 and StartActive to true.

The baker creates the dominant agent archetype in one step:

ComponentPurpose
BnAgentSteeringPosition, velocity, desired velocity, speed, radius and path progress.
BnAgentPathPath slot state and waypoint count.
BnPathWaypointThe path buffer: one element per polygon in the corridor.
BnAgentPathRequestThe pending search request slot.
BnAgentSteeringActiveEnableable toggle for the steering chain.
BnAgentPathRequestPendingEnableable toggle that arms a search request.

The baker sets Start and Target to the spawn position and leaves the request toggle disabled, so the agent stays still until you write a target and arm the request.

3. Systems are discovered automatically

The default world adds both systems to SimulationSystemGroup — nothing to register:

SystemJobOrdering
BnPathfindingSystemBnPathfindJob[UpdateInGroup(SimulationSystemGroup)]
BnSteeringSystemBnFunnelJob, BnSteeringStateJob, KinematicBypassJob, IntegrateJob[UpdateAfter(BnPathfindingSystem)], [UpdateBefore(EndSimulationEntityCommandBufferSystem)]

In a custom World, create both inside its SimulationSystemGroup. Never call OnUpdate manually and never complete their job handles from gameplay code.

4. Request the first path

Add this system to your gameplay assembly. It runs once, writes a target into every baked agent request, and arms the request toggle through the end-of-frame command buffer.

using Unity.Collections;
using Unity.Entities;
using Unity.Mathematics;

namespace BurstNav.Guide
{
    [UpdateInGroup(typeof(SimulationSystemGroup))]
    [UpdateBefore(typeof(BnPathfindingSystem))]
    public partial class BnFirstTargetSystem : SystemBase
    {
        private EndSimulationEntityCommandBufferSystem _commandBufferSystem;
        private EntityQuery _agents;
        private bool _issued;

        protected override void OnCreate()
        {
            _commandBufferSystem = World.GetOrCreateSystemManaged<EndSimulationEntityCommandBufferSystem>();
            _agents = GetEntityQuery(ComponentType.ReadWrite<BnAgentPathRequest>());
        }

        protected override void OnUpdate()
        {
            if (_issued || _agents.IsEmptyIgnoreFilter)
            {
                return;
            }

            _issued = true;

            using var entities = _agents.ToEntityArray(Allocator.Temp);
            using var requests = _agents.ToComponentDataArray<BnAgentPathRequest>(Allocator.Temp);
            var commands = _commandBufferSystem.CreateCommandBuffer();

            for (var index = 0; index < entities.Length; index++)
            {
                var request = requests[index];
                if (request.Status == BnPathStatus.Ready)
                {
                    continue;
                }

                request.Target = new float3(3.5f, 3.5f, 0f);
                request.TargetPoly = -1;
                request.Status = BnPathStatus.Pending;
                request.RequestId++;
                commands.SetComponent(entities[index], request);
                commands.SetComponentEnabled<BnAgentPathRequestPending>(entities[index], true);
            }
        }
    }
}

The command buffer plays back at the end of frame 0. On frame 1 BnPathfindingSystem sees the enabled request, runs flat A* to the nearest polygon of the target, and writes the corridor into the waypoint buffer. The steering system then re-enables BnAgentSteeringActive and the agent starts moving.

Use a payload that matches the baked agent:

FieldValue for the first request
StartKeep the spawn position.
TargetWorld space on the XY plane; Z is height.
TargetPoly-1 asks the pathfinder to snap the target to the nearest polygon.
RequestIdYour own monotonic counter — the pipeline copies it through and never compares it.

5. Verify the first moving agent

Enter Play mode and inspect the Agent entity in the Entities Hierarchy.

FrameWhat you should see
0BnAgentPathRequestPending turns on at the end of the frame.
1BnAgentPath.Status becomes Ready and WaypointCount is greater than zero.
2 and laterBnAgentSteering.Position moves toward (3.5, 3.5, 0); WaypointIndex and PathProgress grow.
ArrivalBnAgentSteering.Flags contains Arrived and DesiredVelocity returns to zero.

If the agent stays still, work through this list in order:

  1. The world has exactly one BnBlobMeshGraph whose Value.IsCreated is true.
  2. The agent carries all six components and its request toggle is enabled.
  3. BnPathfindingSystem and BnSteeringSystem exist and are enabled.
  4. Burst is enabled and the Console shows no job safety errors.
  5. The graph is not empty and a route exists between the resolved polygons.

An off-graph start behaves like an off-graph target: both polygons are snapped to the nearest one. A failure therefore means an empty graph (the snap yields -1), no route, or an exhausted MaxIterations budget — in all three cases BnAgentPath.Status becomes Failed and the corridor is cleared.

6. Build the blob without a SubScene

The same graph can be created from code. Call this one-shot setup before agents run, and dispose the blob when the graph entity is destroyed:

using Unity.Entities;
using Unity.Mathematics;

namespace BurstNav.Guide
{
    public static class BnRuntimeGraph
    {
        public static Entity Create(EntityManager entityManager, int cellsX, int cellsY, float cellSize, float2 origin)
        {
            var blob = BnMeshAuthoringBaker.BuildGraph(cellsX, cellsY, cellSize, origin);
            var entity = entityManager.CreateEntity(typeof(BnBlobMeshGraph));
            entityManager.SetComponentData(entity, new BnBlobMeshGraph { Value = blob });
            return entity;
        }

        public static void Destroy(EntityManager entityManager, Entity entity)
        {
            var blob = entityManager.GetComponentData<BnBlobMeshGraph>(entity).Value;
            if (blob.IsCreated)
            {
                blob.Dispose();
            }

            entityManager.DestroyEntity(entity);
        }
    }
}

BuildGraph returns a persistent blob owned by the caller, unlike the authoring baker whose blob is owned by the baking system. Both Free samples use this path: they build the graph at Play start, so their scenes need no bake step at all.

🧠 How It Works

BurstNav Free is a small, explicit pipeline: a polygon graph feeds a flat A* search, the search fills a waypoint buffer, and a kinematic funnel turns that corridor into a desired velocity. This page defines the data and the invariants you rely on when you read or extend the code.

🧭 Frame flow

BnAgentPathRequest (target written by gameplay, toggle armed)
  -> BnPathfindingSystem / BnPathfindJob
  -> flat A* over BnMeshGraphBlob with one shared BnPathScratchpad
  -> BnAgentPath + BnPathWaypoint buffer (corridor)
  -> BnSteeringSystem / BnFunnel.Solve
  -> BnAgentSteering.DesiredVelocity
  -> KinematicBypassJob
  -> BnAgentSteering.Velocity
  -> IntegrateJob
  -> BnAgentSteering.Position

Two systems, five jobs, six agent components. Nothing else runs.

🗺️ Graph, polygons and portals

A navigation graph is an immutable polygon soup stored in a blob asset. Every polygon is convex, and two polygons that share an edge are neighbours.

BnMeshGraphBlob stores four flat pools plus per-polygon index tables:

FieldContents
VerticesAll polygon vertices as float2, in graph space on the XY plane.
PolygonsOne BnPolygon per polygon: centre, vertex offset and count, neighbour offset and count.
NeighborPolygonsFlat list of neighbour polygon ids, grouped per polygon.
LinksFlat list of directed portals between neighbours.
PolyLinkOffsetsFirst link index owned by each polygon.
PolyLinkCountsNumber of links leaving each polygon.

Polygon ids are stable integers: Free never reorders or reuses them, so gameplay can store an id and compare it later. Read the graph through its accessors rather than walking the pools:

AccessorReturns
PolygonCount / LinkCount / VertexCountPool sizes.
GetPolygonCenter(id)Polygon centre (heuristic anchor).
GetPolyLinkOffset(id) / GetPolyLinkCount(id)The polygon's slice of Links.
GetPolyLink(id, index)One BnLinkData.
GetNeighborCount(id) / GetNeighbor(id, index)Neighbour polygon ids.
GetVertexCount() / GetVertex(index)Vertex pool access.

A branch-free nearest-polygon query looks like this:

using Unity.Mathematics;

namespace BurstNav.Guide
{
    public static class BnPolygonLookup
    {
        public static int NearestPolygon(ref BnMeshGraphBlob graph, float3 position)
        {
            var point = new float2(position.x, position.y);
            var best = -1;
            var bestDistanceSq = float.PositiveInfinity;

            for (var polygon = 0; polygon < graph.PolygonCount; polygon++)
            {
                var distanceSq = math.distancesq(graph.Polygons[polygon].Center, point);
                var closer = distanceSq < bestDistanceSq;
                best = math.select(best, polygon, closer);
                bestDistanceSq = math.select(bestDistanceSq, distanceSq, closer);
            }

            return best;
        }
    }
}

The scan is sequential over the polygon table and branch-free inside the loop. It suits one-shot queries, not a per-entity hot loop — the pathfinding system resolves world points to polygons once per request.

Links are directed portals

BnLinkData is one directed portal toward a neighbour:

FieldMeaning
PortalLeft / PortalRightEndpoints of the shared edge, in graph space.
TargetPolygon id reached through this portal.
CostTraversal cost. A non-positive cost makes the search use the centre-to-centre distance.

The same edge exists twice when both directions are traversable — each direction is its own BnLinkData entry with its own cost. The funnel reads the portal endpoints, not the polygon centres, which is why a corridor waypoint carries both a position (usually a centre) and an exit point (the portal midpoint used to leave that polygon).

🧠 Flat A* and the scratchpad

BnAStar.FindPath has one authoritative signature:

bool BnAStar.FindPath(ref BnMeshGraphBlob graph, int startPoly, int targetPoly,
                      ref BnPathScratchpad scratch, int maxIterations)

The heuristic is the Euclidean distance between polygon centres, scaled by BnPathScratchpad.HeuristicScale (default 1, admissible for portal costs). Set it to 0 to degrade to Dijkstra when your cost metric is arbitrary.

The scratchpad is reusable working memory indexed by polygon id. FindPath allocates nothing: a search clears and overwrites the scratchpad arrays in place. Allocate it once with capacity ≥ graph.PolygonCount, reuse it for every query, and dispose it when the owner is destroyed.

using Unity.Collections;

namespace BurstNav.Guide
{
    public static class BnFlatSearch
    {
        public static BnPathSearchStatus Run(
            ref BnMeshGraphBlob graph,
            int startPoly,
            int targetPoly,
            int maxIterations,
            out float pathCost)
        {
            var scratch = BnPathScratchpad.Create(graph.PolygonCount, Allocator.Temp);
            try
            {
                BnAStar.FindPath(ref graph, startPoly, targetPoly, ref scratch, maxIterations);
                pathCost = scratch.PathCost;
                return scratch.Status;
            }
            finally
            {
                scratch.Dispose();
            }
        }
    }
}
Scratchpad fieldMeaning
StatusOutcome of the last search (BnPathSearchStatus).
Path / PathCountPolygon sequence, start polygon first.
PathCostTotal cost of the found path.
IterationsNumber of expanded polygons — compare it against your budget.
BnPathSearchStatusMeaning
FoundA path is available in the scratchpad.
UnreachableThe open set drained without reaching the target.
BudgetExhaustedmaxIterations ran out before the target was expanded.
InvalidInputA polygon id is outside the graph.
CapacityExceededThe scratchpad is smaller than the graph.

The pathfinding system maps every failed search to BnPathStatus.Failed and clears the agent corridor. A budget cut-off is a failure, not a partial path.

📦 Corridor and waypoints

BnAgentPath is the per-agent path slot:

FieldMeaning
PathIndexStable integer identity of the slot.
WaypointCountNumber of valid elements in the buffer.
StatusNone, Pending, Ready, Partial or Failed.
IsFollowableTrue when the count is positive and the status is Ready or Partial.

BnPathWaypoint is one corridor element:

FieldMeaning
PositionWaypoint position on the navigation plane; the last element is the exact target.
ExitPointPortal midpoint used to leave PolyIndex; equals Position for the last element.
PolyIndexPolygon that owns this waypoint.
LinkIndexIndex into the graph link table, or -1 for the final waypoint.

The pathfinder writes one element per polygon in the sequence, so a corridor with n polygons has n waypoints. Elements are blittable and live in an IBufferElementData buffer with an inline capacity of 16 (BnAgentComponents.DefaultPathCapacity) before spilling to heap storage.

🎯 Kinematic funnel

BnFunnel is a string-pulling solver over the portal corridor. Each frame Solve:

  1. Advances the cursor past every portal the agent has already crossed (AdvancePathProgress).
  2. Tightens a left/right cone from the agent position through the remaining portals.
  3. Returns the first funnel corner, or the final waypoint when the string stays straight.

It then writes a planar desired velocity:

direction = normalize(waypoint - position)
DesiredVelocity = direction * Min(MaxSpeed, distance / deltaTime)

Because of the distance / deltaTime clamp an agent cannot overshoot a waypoint at the end of a frame. Z is height and is never steered: DesiredVelocity.z is always zero. When the agent is within max(Radius, 0.05) of the last waypoint, Solve writes a zero desired velocity and sets BnAgentFlags.Arrived.

💡 The arrival tolerance is not a separate field. It is the larger of the agent Radius and BnFunnel.DefaultArrivalRadius (0.05), which keeps a zero-radius agent from jittering on the final point.

Progress tracking

FieldMeaning
WaypointIndexCursor into the path buffer — the waypoint the funnel steers toward.
PathProgress / PathLengthDistance travelled along completed segments and total path length.
FlagsFollowing, Arrived and Blocked bits.
NormalizedProgressSaturated PathProgress / PathLength, or 0 without a path.

AdvancePathProgress moves WaypointIndex forward when the agent crosses the portal separating the current waypoint from the next, and rewrites PathProgress to the sum of completed segment lengths. Solve calls it automatically, so gameplay only reads these fields.

🏃 Kinematic bypass, and why there is no avoidance

Velocity is resolved by KinematicBypassJob, which is intentionally a direct copy:

Velocity = DesiredVelocity

There is no neighbour query, no broadphase and no velocity-obstacle solve in this stage. An agent follows its funnel exactly and treats every other agent as non-existent: two agents on crossing paths can overlap, and a stopped agent never pushes a moving one aside.

This is a deliberate package boundary, not a tuning gap:

  • The Free contract is deterministic waypoint following with zero allocation.
  • Avoidance needs neighbour data and a shared solver that Free does not allocate or schedule.
  • Gameplay that needs separation must provide it at design level — spaced spawn points, one-way lanes, staggered start times.

IntegrateJob then advances the position branch-free:

Position = math.mad(Velocity, DeltaTime, Position)

🧩 Why every stage is job-shaped

JobSchedulingWhy
BnPathfindJobSingle-threadedAll agents share one A* scratchpad.
BnFunnelJobParallelEvery agent owns its steering value and buffer.
BnSteeringStateJobParallelWrites enableable toggles into a ParallelWriter.
KinematicBypassJobParallelPure per-agent copy.
IntegrateJobParallelPure per-agent integration.

No system calls Complete inside OnUpdate; dependencies are chained through SystemBase.Dependency, and enableable commands are played back once at the end of simulation.

📡 Runtime API

Everything below lives in the BurstNav namespace and compiles against SnivelerCode.BurstNav.Runtime. The API is deliberately small: six agent components, one graph component, two static solvers (BnAStar, BnFunnel), two systems and five jobs.

🧾 Components at a glance

ComponentKindFields
BnAgentSteeringIComponentDataPosition: float3, Velocity: float3, DesiredVelocity: float3, MaxSpeed: float, Radius: float, PathProgress: float, PathLength: float, WaypointIndex: int, Flags: BnAgentFlags
BnAgentPathIComponentDataPathIndex: int, WaypointCount: int, Status: BnPathStatus
BnPathWaypointIBufferElementDataPosition: float3, ExitPoint: float3, PolyIndex: int, LinkIndex: int
BnAgentPathRequestIComponentDataStart: float3, Target: float3, RequestId: uint, StartPoly: int, TargetPoly: int, Status: BnPathStatus

Active bits are the point: enabling or disabling an IEnableableComponent flips a bit in the chunk mask and moves no entity between archetypes, so a toggle costs nothing in memory or chunk churn.

🧠 Running a search yourself

BnAStar.FindPath is a public static and Burst-callable:

bool BnAStar.FindPath(ref BnMeshGraphBlob graph, int startPoly, int targetPoly,
                      ref BnPathScratchpad scratch, int maxIterations)

public void Search(ref BnMeshGraphBlob graph, ref BnPathScratchpad scratch, int start, int target)
{
    if (!BnAStar.FindPath(ref graph, start, target, ref scratch, 4096))
    {
        var reason = scratch.Status; // Unreachable / BudgetExhausted / InvalidInput / CapacityExceeded
        return;
    }

    for (var index = 0; index < scratch.PathCount; index++)
    {
        var polygon = scratch.GetPathPolygon(index);
        // use the polygon id
    }
}

Ownership rules for the scratchpad:

  • BnPathScratchpad.Create(polygonCapacity, allocator) allocates once; EnsureCapacity(polygonCount, allocator) grows only when the graph outgrows it.
  • Dispose() must run exactly once. Dispose(JobHandle) releases the arrays after the handle completes — that is how BnPathfindingSystem retires a resized scratchpad without stalling the main thread.
  • The scratchpad is not thread-safe while a search mutates it. One search at a time per scratchpad.

Filtered overloads exist on the same method for searches you run yourself:

bool FindPath(ref BnMeshGraphBlob graph, int startPoly, int targetPoly, ref BnPathScratchpad scratch,
              BnLinkFilter filter, int maxIterations)
bool FindPath(ref BnMeshGraphBlob graph, int startPoly, int targetPoly, ref BnPathScratchpad scratch,
              BnLinkFilter filter, NativeArray<ushort> linkTagMasks, int maxIterations)

BnLinkFilter.PassThrough (the default value) allows every link; a non-zero IgnoreTagged rejects every link with any tag bit; otherwise a link is rejected only when one of its tag bits is inside BlockedTagMask, and AllowBlockedTags waives that block. The Free systems always call the unfiltered overload.

Behavioural details that are easy to miss:

  • BnPathfindJob expands one flat A* per pending agent into the shared scratchpad, so it schedules single-threaded. Required toggle state is enforced by the query (BnAgentPathRequestPending enabled), and the job records the toggle-off command rather than writing enable bits directly.
  • BnFunnelJob runs on a query built with EntityQueryOptions.IgnoreComponentEnabledState, so disabled agents are still visited and a freshly assigned path can reactivate them. It calls BnFunnel.Solve on a local copy and does not write the path slot or the buffer back.
  • BnSteeringStateJob derives IsSteerable from BnAgentPath.IsFollowable and records the toggle in a ParallelWriter, so it can run in parallel with the funnel job.
  • KinematicBypassJob and IntegrateJob run on the active query and skip disabled agents through ChunkEntityEnumerator. IntegrateJob is branch-free and uses math.mad.

📦 Mesh Graph Blob Format

The navigation graph is a single blob asset. This page lists exactly what is inside it, how big it is, and the rules that keep it valid.

🧱 The seven pools

BnMeshGraphBlob
├── Vertices        : BlobArray<float2>       // all polygon corners, graph space (XY)
├── Polygons        : BlobArray<BnPolygon>    // centre + vertex/neighbour slices
├── NeighborPolygons: BlobArray<int>          // neighbour ids, grouped per polygon
├── Links           : BlobArray<BnLinkData>   // directed portals
├── PolyLinkOffsets : BlobArray<int>          // first link index per polygon
└── PolyLinkCounts  : BlobArray<int>          // links leaving each polygon

Access is always offset + count pairs, never a linked structure: A* walks the link pool sequentially from PolyLinkOffsets[polygon] for PolyLinkCounts[polygon] entries, which is exactly what Burst needs to vectorize and prefetch.

📐 Struct sizes

StructFieldsBytes
BnPolygonCenter: float2 (8) + VertexOffset: int (4) + VertexCount: int (4) + NeighborOffset: int (4) + NeighborCount: int (4)24
BnLinkDataPortalLeft: float2 (8) + PortalRight: float2 (8) + Target: int (4) + Cost: float (4)24
vertexfloat28

Field order is already size-descending (8-byte, then 4-byte members), so no alignment padding is inserted.

🔢 Pool sizes for a grid

BnMeshAuthoringBaker.BuildGraph emits a non-indexed grid: each polygon owns its own four vertices and all links are materialised in both directions.

PoolSize for CellsX × CellsY
PolygonsX * Y
Vertices4 * X * Y
Links2 * ((X-1) * Y + X * (Y-1))
NeighborPolygonssame as Links
PolyLinkOffsets / PolyLinkCountsX * Y each

Polygon id is row-major: id = y * CellsX + x. The four vertices of polygon id are its lower-left corner, then clockwise: (x, y), (x+1, y), (x+1, y+1), (x, y+1), scaled by CellSize and offset by Origin.

💡 Vertex duplication is the price of a non-indexed grid. Sharing corners between polygons would cut Vertices by ~4×, but the blob would need an index pool and the funnel would lose its direct corner reads. At the sizes Free targets, the duplication is cheaper than the indirection.

🛠️ Building a blob yourself

Only BnMeshAuthoringBaker.BuildGraph(cellsX, cellsY, cellSize, origin) is public; the BlobBuilder path is internal. That means custom geometry has two options:

  1. Compose from grids. Bake several BnMeshAuthoring entities — each produces its own graph, but only one may be the singleton, so grids are usually combined into a single level grid instead.
  2. Write your own builder. Build a BnMeshGraphBlob with BlobBuilder, keeping the invariants below, then assign it to a BnBlobMeshGraph entity.

🏎️ Performance & Tuning

The Free package has few tuning knobs on purpose: the search budget bounds worst-case pathfinding, and the agent steering fields define speed and stopping distance. Everything else is fixed by the zero-allocation job pipeline.

📊 Cost model

StageComplexityThreading
Polygon resolve + flat A*O(expanded polygons) per requestsingle-threaded (one shared scratchpad)
Corridor writeO(corridor length)same job
Funnel + progressO(corridor length) per agentparallel
BypassO(1) per agentparallel
IntegrateO(1) per agentparallel

Pathfinding dominates, and it is serializer-bound by design: two searches cannot share one scratchpad. Steering, by contrast, scales linearly across cores because each agent owns its state and buffer.

Steady-state allocations are zero. The only heap traffic in the pipeline is a BnPathWaypoint buffer spilling past its inline capacity of 16 when a corridor is longer than 16 polygons — and only once per agent.

🎚️ MaxIterations

BnPathfindingSystem.MaxIterations is the maximum number of A* node expansions per request. Default: DefaultMaxIterations = 4096.

ValueEffect
Too lowLong paths end as BnPathStatus.Failed and the corridor is cleared.
4096 (default)Covers most levels up to a few thousand polygons.
LargerTolerates longer or more obstructed routes, but bounds a bad request less tightly.

One expansion pops one polygon and relaxes its outgoing links, so the budget only has to exceed the number of polygons the search expands before it reaches the target. An unreachable target drains the open set and stops early, which costs at most one expansion per reachable polygon. A budget cut-off is a separate outcome.

Set the field once, before agents start requesting paths:

using Unity.Entities;

namespace BurstNav.Guide
{
    [UpdateInGroup(typeof(InitializationSystemGroup))]
    public partial class BnTuningSystem : SystemBase
    {
        private bool _applied;

        protected override void OnUpdate()
        {
            if (_applied)
            {
                return;
            }

            _applied = true;
            var pathfinding = World.GetOrCreateSystemManaged<BnPathfindingSystem>();
            pathfinding.MaxIterations = 8192;
        }
    }
}

HasScratchpad and ScratchpadCapacity let you assert at startup that the scratchpad covers the graph instead of discovering it on the first long request.

🏃 Speed and arrival

The funnel computes desired speed as Min(MaxSpeed, distance / deltaTime), so an agent cannot overshoot a waypoint at the end of a frame. The arrival test uses max(Radius, BnFunnel.DefaultArrivalRadius) — a larger Radius stops the agent further from the target, and a Radius below 0.05 still stops at 0.05.

💡 There is no acceleration model. The kinematic bypass changes velocity from zero to MaxSpeed in one frame. For smoother motion, lower MaxSpeed or replace the steering chain with your own acceleration-limited version before integration.

🚀 Optimisation order

If the profile says pathfinding is too slow for your level, in this order:

  1. Reduce graph size. Bigger CellSize means fewer, larger polygons — the same level with a quarter of the polygons runs roughly four times cheaper per search.
  2. Request less often. Paths are static; re-request only on a new destination, not every frame.
  3. Raise the budget only after measuring.MaxIterations does not make searches faster — it makes more of them succeed.
  4. Spread requests over frames. One or two long searches per frame keeps a stable frame time; a burst of 50 identical long searches does not.
  5. Replace the pathfinding stage if you need hierarchical search or filtered long routes. That is an architecture change, not a setting.

⚠️ Limitations & Scope

Free is built for small static levels with a modest number of agents. The limits below follow directly from the architecture, so plan around them instead of trying to tune them away.

📉 Flat search scaling

Every request runs one flat A* over the whole polygon graph. Cost grows with the number of expanded polygons, and every agent searches the same graph from scratch — there is no cluster decomposition, no abstract graph and no precomputed long-distance route table.

Graph sizeBehaviour
Tens to a few thousand polygonsThe default 4096-expansion budget covers typical paths.
Several thousand polygonsRaise MaxIterations or long routes may fail.
Tens of thousands of polygonsEach request becomes expensive, and the scratchpad grows with the graph.

The scratchpad is O(polygon count) in memory — roughly 29 bytes per polygon plus 12 bytes of spare heap and visit-stamp slots. It is reused, so it never allocates per frame, but it must cover the whole graph: a large graph has a fixed memory floor even when agents only travel short distances.

Pathfinding is also all-or-nothing. When the budget runs out, the request becomes BnPathStatus.Failed and the corridor is cleared — Free never emits a partial path for the agent to follow toward the target.

👥 No crowd avoidance

Free has no neighbour query and no local avoidance solve. KinematicBypassJob copies DesiredVelocity into Velocity unchanged, so every agent follows its funnel as if no other agent existed.

Observable effects:

  • Agents on crossing paths can overlap.
  • A stopped agent does not block or deflect a moving agent.
  • Dense groups do not separate, queue or spread out around corners.
  • Throughput through a narrow portal is not regulated.

The funnel still produces smooth single-agent paths through portal edges. What is missing is social: nothing in Free reads another agent's position or velocity during steering.

If your design needs separation, provide it outside the runtime — spaced spawn points, one-way lanes, staggered start times. A custom post-steering separation job replaces the Free steering contract and is therefore not part of the supported pipeline.

🧱 No dynamic obstacles

The navigation graph is an immutable blob asset. There is no runtime obstacle store, no obstacle query and no broadphase to update when a blocker moves.

  • Moving a wall, crate or vehicle does not change the graph or the agent paths.
  • An agent keeps following its corridor even if something now occupies it.
  • Adding or removing blocked regions requires rebuilding the blob and replacing the graph singleton.
  • There is no built-in push-out when an agent overlaps a static or moving blocker.

You can bake a different graph for a different level state, but swapping graphs at runtime invalidates existing corridors and can force every agent to repath. That is not a supported dynamic-obstacle workflow.

🚪 No door or area tags

Free links carry no door or area tags, and BnPathfindingSystem always runs the unfiltered A* overload. Every portal in the graph is traversable.

  • You cannot close a doorway for one agent and leave it open for another.
  • You cannot route around a locked area through the Free systems.
  • Access control must be enforced by gameplay before a request is issued, and the graph must not contain the forbidden region.
  • A closed door is a graph change — a rebake and a repath, not a per-link flag.

BnAStar.FindPath does expose filtered overloads that take a BnLinkFilter plus an optional per-link tag-mask array, and BnLinkFilter ships in this assembly. Using them requires your own job or system: BnPathfindJob always passes BnLinkFilter.PassThrough with no tag masks, so a filtered search is not reachable through BnPathfindingSystem.

🌐 Static graph, one owner

Free assumes one static graph per world:

  • Exactly one BnBlobMeshGraph singleton. Both systems skip their work when there is none — and when there is more than one.
  • A graph must exist before agents request paths: BnPathfindingSystem returns early while graph.Value is not created.
  • Topology is fixed for the lifetime of the blob. Replacing the blob while searches are in flight is not supported by the Free systems.

📐 2.5-D navigation

Paths and steering are solved on XZ only:

  • No ramp or stair following, and the pipeline never modifies agent Y — vertical movement is gameplay's job.
  • A multi-floor level flattens into one plane, so a "vertical" route is a straight XZ shortcut.
  • Polygons must be convex, and BnMeshAuthoring produces axis-aligned squares only.
  • A spawn or destination far outside the mesh resolves to the nearest polygon rather than failing, which can look like a path that starts in the wrong place.

🔧 Extending beyond Free

Free stops at the architecture on this page. If a level needs more, the options are:

  • Replace or wrap the steering system when agents must stay apart in crowds, queues or narrow corridors.
  • Replace the pathfinding job when the flat search is the frame-time bottleneck, long routes hit MaxIterations, or paths need a different filter.
  • Rebuild and swap the graph blob when obstacles move or the level changes — never while searches are in flight.
  • Enforce doors and areas before a request is issued, or write a filtered search job around BnAStar.FindPath.

Each option replaces a pipeline stage rather than changing a field, because the package deliberately exposes no extension points: six agent components, five jobs and two systems are the whole contract.

🚑 Troubleshooting & FAQ

🔍 Agent does not move

Work through this list in order — it covers every cause we know of.

#CheckFix
1Is there exactly one BnBlobMeshGraph with Value.IsCreated?Bake the graph in a SubScene, or call BnMeshAuthoringBaker.BuildGraph once at startup.
2Does the agent carry all six components?Use BnAgentAuthoring or BnAgentComponents.CreateAgentArchetype.
3Is BnAgentPathRequestPending enabled?Enable it after writing a target — a freshly baked agent has it off by design.
4Did you write a Target different from Start?The baker sets both to the spawn position.
5Are BnPathfindingSystem and BnSteeringSystem present and enabled?Check Window → Entities → Systems; in a custom world, create both inside SimulationSystemGroup.
6Is BnAgentSteeringActive enabled?BnSteeringStateJob turns it on when a path becomes followable; a manual false keeps the agent frozen.
7Is Burst enabled with no job safety errors?Fix the first console error before anything else.

❌ BnAgentPath.Status is Failed

Three causes, in order of likelihood:

CauseSymptomFix

🧭 The agent walks in a straight line through walls

CauseFix
Z was used as the navigation planePathfinding is XZ only: put the level on XZ and use Y for height.

👥 Agents pass through each other

That is the documented behaviour. KinematicBypassJob copies DesiredVelocity into Velocity and reads no neighbour data, so Free has no separation stage. Use spaced spawn points, one-way lanes, staggered start times, or replace the steering system — see Limitations & Scope.

🚧 Moving obstacles are ignored

The graph is an immutable blob and there is no obstacle store. Rebuild the blob for a new level state, or keep obstacles out of the walkable graph. There is no push-out when an agent overlaps a blocker.

🚪 Doors do not close

Free links carry no tags and the systems always run the unfiltered search. Enforce access in gameplay before issuing a request, or write a custom job around BnAStar.FindPath's filtered overloads.

🧩 Nothing runs after adding a second graph

Both systems require a singleBnBlobMeshGraph. With two, TryGetSingleton fails and the systems early-out — silently. Check the world for duplicate baked navmesh objects, including graphs imported with a sample.

❓ FAQ

Does Free support slopes, stairs or multiple floors?
No. Navigation is XZ only; the pipeline never modifies agent Y. Vertical movement is your gameplay's job, and a multi-floor level flattens into one plane.

Can I use a custom mesh instead of the grid?
Yes, by writing your own BlobBuilder code that produces a valid BnMeshGraphBlob — see the invariants in Mesh Graph Blob Format. BnMeshAuthoring itself only emits grids.

Can I have two graphs and switch between them?
Not through the Free systems: they require exactly one singleton, and replacing the blob while searches are in flight is unsupported. Build one graph per level.

Is this a NavMesh replacement?
For static, moderate-size levels with per-agent movement, yes. It is not a replacement for crowd simulation, dynamic obstacles or off-mesh links.

Do I need a SubScene?
No. Both samples build the graph from code at Play start (BnMeshAuthoringBaker.BuildGraph). A SubScene is just the convenient path for level designers.

Is the result deterministic?
Yes, given the same graph, the same requests and the same frame delta. BnPathfindJob is single-threaded over a stable polygon ordering, and steering is per-agent with no shared state.

What happens if a corridor is longer than 16 polygons?
The BnPathWaypoint buffer spills from inline storage to the heap once for that agent. Paths of 16 or fewer polygons are allocation-free.

Does RequestId cancel a stale request?
No. It is copied through untouched; compare it yourself if you issue overlapping requests.

Which Unity versions are supported?
Unity 2022.3 and newer with Entities 1.x. It is verified in Unity 6000.5.2f1 with com.unity.entities 6.5.0.
